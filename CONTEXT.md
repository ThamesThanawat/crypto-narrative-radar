# CONTEXT.md

## Project Context

Crypto Narrative Radar is a Python-based market intelligence and research support project for analyzing crypto narrative momentum using CoinGecko market data.

The project transforms token-level market data into narrative-level insights across sectors such as:

- Layer 1
- Layer 2
- DeFi
- RWA
- AI
- DePIN
- Gaming / GameFi
- Exchange Tokens

The project is designed as a recruiter-ready portfolio project demonstrating:

- Python
- pandas
- API integration
- data cleaning
- SQL analytics
- market taxonomy
- narrative-level analysis
- research scoring methodology
- report/dashboard output
- crypto market research thinking
- product sense

## Important Positioning

Crypto Narrative Radar is not a trading bot.

Do not describe the project as:

- a price prediction model
- a trading signal generator
- an alpha-generating strategy
- a buy/sell recommendation engine
- a portfolio optimizer
- a backtesting system

Use this framing instead:

Crypto Narrative Radar is a market intelligence and research support tool that helps monitor narrative-level momentum, relative strength, volume confirmation, and breadth of participation across crypto sectors.

The outputs support research, market monitoring, and investment screening workflows. They do not recommend trades.

## Core Domain Terms

### Token Universe

The curated list of tokens tracked by the project.

The token universe is representative, not exhaustive. It is designed to be liquid, recognizable, explainable, and suitable for a recruiter-ready MVP.

### Primary Narrative

The main research basket assigned to a token.

Each token should have exactly one primary narrative for MVP scoring and aggregation.

Example:

```text
RENDER -> AI
BNB -> Exchange Tokens
LINK -> RWA
```

### Secondary Narratives

Additional narrative tags used for research context.

Secondary narratives are not double-counted in MVP scoring.

Example:

```text
RENDER
primary_narrative = AI
secondary_narratives = DePIN; compute
```

### Market Snapshot

A point-in-time dataset of token-level market data pulled from CoinGecko.

A market snapshot includes prices, market cap, volume, returns, and last updated timestamps.

### Narrative Metrics

Aggregated statistics by primary narrative.

Examples:

- token_count
- median_return_7d
- median_return_30d
- total_market_cap
- total_volume
- breadth_7d
- relative_strength_7d

### Narrative Ranking

The ranked output created from narrative metrics.

The ranking is based on the Narrative Momentum Score.

It is a research ranking tool, not a trading signal.

### Narrative Momentum Score

A composite research score from 0 to 100.

Current V1 framework:

```text
40% price momentum
25% relative strength
20% volume confirmation
15% breadth of participation
```

The score helps compare narrative-level market momentum. It does not predict future prices.

### Price Momentum

A measure of recent token or narrative returns.

In V1, price momentum uses 24h, 7d, and 30d return windows.

### Relative Strength

A measure of how a narrative performs compared with benchmark crypto assets such as BTC and ETH.

Example:

```text
rs_vs_btc_7d = median_return_7d - btc_return_7d
rs_vs_eth_7d = median_return_7d - eth_return_7d
```

Relative strength helps identify whether a narrative is outperforming broader crypto benchmarks.

### Volume Confirmation

A liquidity and attention proxy.

In this project, volume confirmation uses volume relative to market cap.

Example:

```text
volume_to_market_cap = total_volume / market_cap
```

High volume confirmation suggests market activity is supporting the move, but it is not proof of fundamental adoption.

### Breadth of Participation

The share of tokens inside a narrative with positive returns over a given time window.

Example:

```text
breadth_7d = number of tokens with positive 7d return / total tokens in narrative
```

Broad participation is stronger than a move driven by only one token.

### Concentration Review

A diagnostic view showing whether a narrative is dominated by one or a few large tokens.

Examples:

- top_1_market_cap_share
- top_3_market_cap_share
- concentration_comment

Concentration review is not part of the Narrative Momentum Score V1. It is used for interpretation.

### Token Contributors

Tokens that drive narrative-level performance, volume, or market cap.

Token contributor analysis helps answer:

```text
Which tokens are driving this narrative?
Is the narrative move broad or concentrated?
Is volume leadership coming from one token or many?
```

### Data Quality Flag

A field that marks missing or incomplete market data.

Examples:

- ok
- missing_price
- missing_market_cap
- missing_volume
- missing_7d_return
- missing_30d_return
- missing_last_updated

The project should not silently hide data quality issues.

## Research Interpretation Rules

Use cautious research language.

Good language:

- narrative momentum increased
- relative strength improved
- volume confirmation strengthened
- breadth expanded
- participation narrowed
- the move appears concentrated
- the narrative is outperforming BTC/ETH over the selected window
- this may warrant deeper research

Avoid language such as:

- buy
- sell
- guaranteed upside
- alpha signal
- price prediction
- this will pump
- sure opportunity
- profitable strategy

## SQL Analytics Role

The SQL analytics layer uses DuckDB to query processed CSV outputs.

The SQL layer is used for:

- SQL-based narrative summary
- top token contributor analysis
- concentration review
- analytics transparency
- demonstrating SQL skills

The SQL layer should not replace the pandas scoring pipeline.

Use this rule:

```text
pandas = source of truth for data cleaning and scoring
SQL = query, review, and analytics layer
```

Do not add:

- PostgreSQL
- database server
- Docker
- dbt
- Airflow
- scheduler
- trading logic

## Interview Explanation

A simple explanation of the project:

```text
Crypto Narrative Radar is a Python-based crypto market intelligence project. It starts with a curated taxonomy of tokens grouped by narrative, pulls market data from CoinGecko, cleans the data with pandas, aggregates token-level data into narrative-level metrics, ranks narratives using a transparent momentum framework, and adds a DuckDB SQL layer for contributor and concentration analysis.
```

A short explanation of the score:

```text
The Narrative Momentum Score is a research ranking tool. It combines price momentum, relative strength versus BTC and ETH, volume confirmation, and breadth of participation. It is designed to help compare narrative-level market activity, not to predict prices or generate trading signals.
```

## Completed Milestones

- Milestone 5.8A: Historical Token Backfill V1

### Milestone 5.8A Summary

Historical Token Backfill V1 adds a token-level historical market data foundation using CoinGecko `/coins/{id}/market_chart`.

The pipeline:
- reads validated CoinGecko IDs from `data/reference/taxonomy.csv`
- fetches 90-day daily historical market data
- saves raw JSON responses under `data/raw/coingecko/historical/YYYY-MM-DD/`
- logs failed tokens in `backfill_failures.csv`
- normalizes data into `data/processed/historical/token_market_history_90d.csv`
- calculates token-level calendar-lag returns: `return_1d`, `return_7d`, and `return_30d`
- adds `data_quality_flag`
- validates the historical token output

Latest run:
- requested tokens: 80
- successful tokens: 77
- failed tokens: 3
- failed due to CoinGecko 429 rate limits: `curve-dao-token`, `ondo-finance`, `render-token`
- processed rows: 6,930
- date range: 2026-02-22 to 2026-05-22
- tests passed: 44 passed

Scope note:
Milestone 5.8A does not add narrative historical metrics, historical scoring, dashboard charts, SQL changes, backtesting, prediction logic, or trading signals.
